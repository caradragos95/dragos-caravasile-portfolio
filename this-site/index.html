Case study 03 · Verification

This site shipped broken and looked fine.

Built by AI agents across two sessions. Seven defects reached the live site. Not one of them was visible by looking at the page.

2026Self-auditWCAGPlaywright
01 / What was wrong

Seven defects, none of them visible.

The first build of this page was produced by one agent and looked complete. It was published, shared, and read. A later measured audit found seven defects already live.

01Headline clipped on every phone, hidden by an overflow:hidden on its container17px cut at 320px
02Whole page scrolled sideways, because grid items default to min-width:auto8px at 320px
03Two of five numerals invisible: orange on violet, and orange on the same orange1.22:1 and 1:1
04Small labels below the accessible contrast floor on two backgrounds2.34:1, needs 4.5:1
05Favicon requested from the domain root, not the site path404 on every load
06No social card metadata, so every link shared to LinkedIn rendered as a bare grey boxthe primary CTA
07No keyboard focus indicator anywhere, and no reduced-motion handlingunusable without a mouse

All seven were live. All seven pass a visual review.

02 / Why nobody caught them

Every one of them reviews clean.

A contrast ratio of 1.22:1 is not something an eye reports as an error. It reads as an empty corner, a design choice, a bit of negative space. Thirteen pixels of a clipped headline read as tight tracking. A missing social card is invisible until somebody else shares the link, at which point you are not watching.

These share one property, and it is the same property that makes documentation dangerous. They produce output that is confidently wrong and survives every review that consists of looking at it. The reviewer's agreement is not evidence, because the reviewer is running the same faulty check as the author.

The parallel is exact. A config value transcribed from source code looks right, reads right, and does nothing. A page whose numerals sit at 1:1 against their background looks designed. Neither error announces itself, so neither can be caught by attention. Only by measurement.

03 / What actually found them

Compare the rendered page against a number.

Every defect above was found the same way: render the page in a real browser, extract a value from the live DOM, and compare it against a threshold that does not depend on judgement.

Layout defects came from comparing content width against container width at fifteen viewport sizes from 320px to 1920px. Contrast defects came from computing WCAG ratios on the resolved colours rather than on the palette as designed, which is what exposed the numerals: the palette was fine, the inheritance was not.

// the check that found defect 01 h1.scrollWidth 371 h1.getBoundingClientRect().width 358 ^ 13px of headline, clipped and silent // the check that found defect 03 contrast(computed color, computed background) numeral 02 1.22:1 numeral 04 1.00:1 orange on orange after fix 16.10:1

Two of the seven checks. Neither requires an opinion.

04 / The part worth admitting

The fix pass had the same failure mode.

A second agent audited the first agent's work and fixed all seven. While doing so it introduced an eighth defect of exactly the same kind: a row of figures placed inside a dark section, inheriting light text, on a light background it had set itself. The first value rendered invisible. Paper on paper.

It was caught before merge, by the same contrast check that found the original two. That is the only reason it is an anecdote rather than a defect.

The same thing happened in the writing. Three thousand words of case studies came back containing seven instances of a sentence construction that this project's own style guide bans in its opening lines. Fluent, consistent, confidently wrong, and invisible until the text was read as a whole against the rule rather than sentence by sentence.

Two agents, two sessions, one failure mode. Generated work is plausible by construction. That is its purpose and its defect, and it does not improve by being reviewed harder by someone reading it.

05 / What it means for the work

Trade-offs.

What AI was good at

A complete, distinctive, responsive site from nothing. The design holds up. The structure is sound. Every defect above is a detail, and none of them is the hard part of making a page.

What it could not do

Know what it got wrong. Nothing in generated output signals its own confidence, so the only durable answer is a check that returns a number and a threshold that is not up for debate.

Which is the same conclusion the documentation work reached, arrived at from the other direction. Verify against something computable, encode the rule once the failure has happened, and never accept fluency as evidence. This page is the argument tested on its own author.
